# 생성 광고 보고서

`generation-cadence-v4`는 기존 이용자 배정을 유지합니다. `control`은 A(이후 2~8회),
`short`는 B(이후 2~5회)입니다. 양쪽 모두 하루 생성 성공 1회로 출석할 수 있고,
첫 광고 간격은 1~3회, 재방문 첫 생성 광고 조건도 같습니다. 광고 후 간격에는
그 광고 CTA로 바로 생성한 1회도 포함됩니다. 랜덤 추첨과 남은 횟수는 클라이언트에만
두며 지표 수집이 횟수나 기능 이용을 승인하지 않습니다.

클라이언트 출시 전에 순방향 마이그레이션과 WASM을 배포합니다. 기존 v3 앱은 기존
응답 버전과 공통 광고 그룹을 계속 사용합니다. v4 참여 후에는 구버전으로 돌아가도
출석 조건이 다시 높아지지 않습니다. 배정은 고정하고 첫 v4 카운터만 새로 추첨합니다.
단, 처리 중인 이전 광고 안내는 스킵권 복구를 위해 유지합니다. 이후 앱 업데이트는
v4 카운터를 초기화하지 않으며 기존 보상·스킵권 잔액도 유지합니다.

서버가 인증된 이용자로 군을 결정합니다. 비공개 `ait_lotto_generation_ad_groups`의
4개 그룹에 기존 지면 사용 설정·광고 유형 비중·쿨다운·일일 상한을 공통 적용합니다.
그룹 누락 시 공통 그룹으로 조용히 대체하지 않습니다. 테스트 모드는 SDK 테스트 ID만
사용합니다. 수익 범위는 **생성 계속하기 광고**이며 공통 배너·맞춤 생성·분석·출석 복구는 제외합니다.

SQL 에디터에서 `analytics`를 Attached로 선택하고 `22-generation-v4-summary.sql`로
활동과 평가 시점이 지난 D1/D7을 확인합니다. 단말 시계 오차를 피하려고 서버 수신 시각을
사용하며, 전송 지연 때문에 자정 경계가 달라질 수 있습니다. 쿼리의 해석 주석을 함께 읽으세요.

수익 갱신 절차:

1. 앱인토스 `iaa_placement_group_list`에 `includeReport=true`와 조회 시작·종료일을
   지정합니다. 가능하면 종료된 한국시간 날짜를 조회하며 콘솔의 일별 갱신 이후 수집합니다.
   응답의 그룹 배열을 비공개 JSON 파일로 저장합니다.
2. `bun scripts/miniapp/ad-revenue-import.mjs /private/path/groups.json /private/path/import.sql`을 실행합니다.
3. 생성된 SQL을 이 앱의 인증된 SQL 에디터에서 실행합니다. 허용된 날짜·그룹별 집계만
   갱신하며 사용자 보상이나 잔액을 바꾸지 않습니다.
4. `analytics`를 연결하고 `23-generation-v4-revenue.sql`을 실행합니다. 최신 보고서를
   다시 가져오면 정정 금액이 반영됩니다. 누락/null은 0원이 아닌 **미수집**입니다.
   양쪽 광고 유형이 수집돼야 군별 일 합계가 완성되며 부분 수익은 따로 표시합니다.
   누락된 날짜를 임의로 0원 처리하지 마세요.

금액은 원 단위 예상수익이며 확정 정산이 아닙니다. 차액은 참여 이후 신청 시점의 최근 관측 실험이 v4인
출석 지급성공액만 차감하며 다른 실험에서 v4로 돌아온 구간도 포함합니다. 관측이 없으면
참여 실험을 사용하므로 수집 누락에 따른 비용 귀속 오차가 남습니다. 공통 지면 수익·운영비·미신청/미래 보상이 빠져 있어
순이익으로 해석하면 안 됩니다. 주간 보상은 이전 출석의 영향을 포함할 수 있으므로 보상
정책과 관측기간을 맞춰 비교하세요. 지표는 45일 보관되고 탈퇴 시 활동·참여 기록이 삭제되므로
운영 비교용이며 변경 불가능한 회계 마감 자료가 아닙니다.

보상 유예 종료는 런타임 설정 `AIT_REWARD_LEGACY_POINTS_ENDS_AT`(epoch 밀리초, 해당
시각 미포함)입니다. 출시 전 Coolify와 마운트된 런타임 설정에서 확인하세요. 캠페인 종료일이나
획득 보상의 청구기한으로 추정하지 마세요. 이미 획득한 보상은 기존 청구기한까지 유지합니다.
자세한 운영 절차는 `OPERATIONS.md`를 참고하세요.


SQL 에디터의 24번은 11월 6일(KST)부터 기존 두 광고 간격의 스킵권 사용률, 생성 광고 수익, D1·D7 서버 재방문을 일별로 비교합니다. 2.0.0까지의 v4 번들은 노출 이벤트를 서버에 전송하지 않아, 당일 활동의 기준으로 배정 이후 서버 거래를 사용합니다. 수익 보고서가 양쪽 포맷 모두 도착해야 원화 합계가 표시됩니다.
