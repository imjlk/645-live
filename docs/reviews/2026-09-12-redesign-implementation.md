# 645.live 개편 구현 기록

2026-09-12 기준. [구현 전 검토](2026-09-12-design-revenue-seo.md)의 디자인·문구·SEO·광고 측정 개선을 기존 SvelteKit 앱에 반영했다. 이 기록의 수익 관련 내용은 측정 가능한 구현과 운영 실험 계획이며, 실제 수익 상승을 의미하지 않는다.

## 화면·여백·테마

- 공통 본문 너비는 최대 1240px, 좌우 여백은 `--page-gutter`의 16–32px, 주요 절 간격은 `--section-space`의 28–48px이다. 각 페이지의 `content-page`가 본문 여백을 한 번만 담당한다. 뉴스 본문은 읽기 너비를 별도로 제한한다.
- 헤더·모바일 5개 탭·전체 메뉴·푸터를 통합했다. 모바일 하단 탐색 높이 64px에 기기 safe area를 더하고 본문 하단 공간을 확보한다. 본문 건너뛰기, 키보드 포커스, 동작 줄이기 설정을 지원한다.
- daisyUI 5의 `--color-*` 토큰으로 라이트와 다크를 정의했다. 화면 테마에서 기기 설정·라이트·다크를 선택한다. 선택은 `645-theme`에 저장하며 첫 화면 그리기 전에 적용한다. 시스템 설정 변경과 다른 탭의 선택 변경도 반영한다. 저장소 접근이 제한되면 현재 화면에 적용한다.
- 당첨번호 공의 다섯 색과 글자색을 공통 토큰으로 정리했다. 스캔·공식 추첨·보너스의 의미는 문구와 레이블로 구분한다.
- 홈은 발표된 당첨번호·1등 당첨금·QR 확인·번호 만들기를 먼저 보여준다. 데이터가 없으면 빈 상태를 표시한다. 판매 중 회차의 스캔 집계는 별도로 제공한다.
- 통계는 범위·결과·상세 분석 순서로 정리하고, 불필요한 소개 카드와 중첩 여백을 줄였다. 번호 통계와 사이트 스캔 통계를 구분했다.
- 생성기는 기본 생성·결과·복사를 먼저 제공한다. 조건은 펼쳐서 변경하고 통계는 펼칠 때 한 번 조회한다. 입력 조건 검사, 반복 상한, 작업 중 브라우저 양보를 적용했다. 생성 후 조건 변경은 결과에 표시한다.
- 회차 결과는 최신 발표 회차가 기본이다. 판매점은 등수·주소 기준 지역·상호/주소 검색을 제공한다. QR은 카메라·사진 입력과 결과를 한 작업 영역에 두고 집계를 접었다. 기존 스캔 저장·중복 처리·회원 연동은 유지했다.

## 문구·검색 정보

- 카드용 `summary`와 검색용 `seoDescription`을 분리했다. 기존 `description`도 요약 호환 필드로 유지한다. 뉴스 생성기의 JSON 스키마·프롬프트·검증·fallback·MDX 출력에 함께 반영했다.
- 기존 37개 기사에 고유한 115–129자 검색 설명을 넣었다. 원 당첨번호·금액·표·작성자·발행/수정 시각을 보존하고 일부 산술 오류·중복 문구·미완성 문장을 바로잡았다.
- 일반 페이지와 번호·기간별 통계의 설명도 페이지 내용에 맞게 확장했다. 길이는 내부 편집 기준이며 검색엔진이 정한 고정 글자 수가 아니다. Bing 경고의 해소 여부와 검색 결과 문구는 재수집 후 별도 확인해야 한다.
- 기간별 제목에 실제 분석 회차 수를 넣고, 잘못된 번호 경로는 404를 반환한다. 홈의 에이전트 보기에는 `noindex,follow`를 적용했다. 상태 페이지 H1 중복을 해소하고 안내 페이지에도 기본 OG/Twitter 정보를 제공한다.
- 정적 사이트맵에 소개·출처·편집·연동 안내 등을 포함했다. 파일 복사 시각을 `lastmod`로 쓰지 않는다. 통계 사이트맵은 실제 데이터 시각을 이용하고 확인할 수 없으면 날짜를 생략한다. `robots.txt`에 두 사이트맵을 명시한다.
- 뉴스 OG 이미지 버전을 갱신해 이전 일반 대체 이미지 캐시와 새 기사 정보를 분리했다.
- 기존 URL과 회차 필터의 canonical 정책을 유지한다. 회차별 독립 검색 랜딩 신설은 유입 분석 후 별도 검토한다.

## 광고와 측정 운영

기존 AdSense 게시자 ID·자동 광고 스크립트·GA4·Clarity를 유지했다. 개발 환경에서는 광고와 운영 측정 전송을 껐다. 자동 광고의 계정 설정은 변경하지 않았다.

수동 광고를 켜려면 배포 환경의 `PUBLIC_ADSENSE_SLOTS`에 **실제 AdSense 광고 단위 ID를 문자열로** 매핑한다. 기본값은 `{}`이며 미설정·잘못된 ID는 광고 컴포넌트와 예약 공간을 만들지 않는다. 광고 단위 ID는 비밀 정보가 아니며 브라우저에 전달된다.

| 설정 키 | 위치 |
| --- | --- |
| `home-inline` | 홈의 당첨 결과·확인 도구 다음 |
| `home-rail` | 홈의 데스크톱 보조 열 |
| `stats-inline` | 통계 허브 및 번호 상세 핵심 내용 다음 |
| `history-inline` | 실제 회차 결과 다음 |
| `stores-inline` | 판매점 10개 다음 또는 짧은 결과 목록 끝 |
| `news-inline` | 뉴스 목록의 네 번째 일반 기사 다음 |
| `article-inline` | 기사 핵심 결과·해설 다음 |
| `generator-inline` | 생성 결과가 있을 때 작업 영역 다음 |

광고는 화면 근처에서 한 번 초기화한다. 경로 변경 시 해당 슬롯을 다시 만들며 자동 새로고침하지 않는다. 최소 공간을 예약하고 미채움 상태에는 이용 가이드를 표시한다. QR 카메라·로그인·회원 이력에는 수동 슬롯을 넣지 않았다.

**자동 광고는 별도 설정이다.** 위 슬롯 구현은 AdSense 자동 광고의 앵커·전면·본문 삽입을 차단하지 않는다. AdSense에서 QR·로그인·내 기록의 페이지 제외, 카메라/입력/생성 버튼의 제외 영역, 모바일 하단 탐색과 앵커 중첩을 점검한다. 본문 제외 영역은 오버레이 형식을 제어하지 않으므로 형식 설정도 따로 확인한다. 자동 광고와 수동 슬롯을 동시에 켤 때 전체 밀도를 함께 비교한다.

| 이벤트 | 의미 |
| --- | --- |
| `navigation_click` | 내부 링크의 도착 경로와 클릭 영역 |
| `generate_complete` | 조건에 맞는 번호 생성 완료 |
| `qr_scan_complete` | 성공한 스캔 처리 완료 |
| `ad_slot_request` / `ad_slot_filled` | 수동 슬롯 초기화 / AdSense 채움 상태 |
| `ad_slot_visible` | 채워진 슬롯 영역이 화면의 50% 이상에서 1초 연속 보인 자체 관찰값 |
| `web_vital` | web-vitals의 LCP·INP·CLS 값·등급 |

QR 내용·계정 ID·URL 쿼리는 새 이벤트 매개변수에 넣지 않는다. 자체 `ad_slot_visible`은 광고 프레임 내부를 검증하는 Google Active View 공식 수치가 아니므로 구분해서 사용한다. GA4에 필요한 사용자 정의 측정기준을 등록하고 AdSense 수익 보고와 기간·시간대·기기 기준을 맞춘다.

배포 전후 같은 요일 구성을 포함한 기간에서 페이지 유형별 Page RPM·총수익·세션당 수익, QR/생성 완료, 다음 페이지 이동, 재방문, 실제 사용자 p75 LCP/INP/CLS를 비교한다. 광고 위치·개수·형식은 한 번에 한 변수씩 시험한다. 계정 지표가 제공되지 않아 이번 변경의 수익 상승률은 산정하지 않았다.

## 검증과 배포

- `bun run www check`: 오류 0, 경고 0.
- `bun run www build`: Cloudflare 어댑터·사이트맵 생성 포함 성공.
- `bun run lint`: 종료 코드 0. Svelte 템플릿 사용 변수 인식 등을 포함한 경고 697개와 안내 21개는 남아 있다. 사용 중인 컴포넌트를 제거하는 unsafe fix는 적용하지 않았다.
- SDK check/build 성공, TrailBase 어댑터 타입체크와 테스트 62개 통과.
- Playwright 회귀 테스트 8개 통과: 테마 저장·시스템 추종, 모바일 메뉴, 잘못된 번호, 기간별 메타, 기사 메타, 기존 WebMCP 등록 범위.
- 대표 13개 화면을 360·768·1280px에서 검사한 39개 경우 모두 가로 넘침·중복 H1·브라우저 실행 오류 없음. 390px 라이트·다크 시각 검증도 수행했다.
- 생성 조건·100게임·잘못된 입력·중단 시간·응답성 검증 통과. QR 카메라 권한 거부와 모의 서버 응답 후 결과·6개 번호 표시를 확인했다. 이 검증에서는 서버 쓰기를 차단했다.
- 빌드 사이트맵 **183개 URL 모두 HTTP 200**, 설명 **102–140자**, 제목·설명 중복 0. 추가 경로를 포함한 190개 검사에서 잘못된 번호 2개는 404, 나머지 페이지는 의도한 메타·canonical·JSON-LD를 제공했다. `/history?round=1240`은 의도적으로 `/history`와 설명·canonical을 공유한다.
- 변경 Svelte 컴포넌트는 autofixer로 검사했다. 신뢰한 숫자 데이터의 기존 HTML 포매터, 외부 링크/쿼리 링크, 상태 동기화 effect에 대한 일반 제안은 동작과 입력 출처를 검토하고 유지했다.

실제 티켓의 운영 저장·실기기 카메라 인식과 실광고 채움은 별도 확인 범위다. 수동 광고 ID가 없어 실광고 수동 슬롯의 성과는 측정하지 않았다. 브라우저 검증은 공개 데이터 조회·로컬 생성·격리한 QR 모의 응답 중심으로 진행했다.

배포 방식은 사용자 지시에 따라 작업 브랜치를 원격에 보관하고, 검증한 변경을 main에 병합·push하여 기존 자동 배포를 이용한다. PR은 생성하지 않는다.

### Cloudflare Git 자동 배포 설정 복구

첫 main push에서 GitHub CI는 성공했으나 Pages는 앱 빌드 전 `npm install`의 `EUNSUPPORTEDPROTOCOL: workspace:*`로 실패했다. Pages의 기존 루트·출력 경로도 모노레포 구성과 맞지 않았다. 프로젝트 설정을 다음과 같이 고쳤다.

| 항목 | 값 |
| --- | --- |
| Root directory | `pages/www` |
| Build command | `cd ../.. && bun install --frozen-lockfile && bun run www build` |
| Build output directory | `.svelte-kit/cloudflare` (Root directory 기준) |
| `BUN_VERSION` | `1.4.0` (로컬 검증 버전, production·preview) |
| `SKIP_DEPENDENCY_INSTALL` | `1` (자동 npm 설치 대신 위 명령 사용) |

빌드 루트를 고치면 Pages는 `pages/www/wrangler.jsonc`의 변수를 우선하므로 `BUN_VERSION`과 `SKIP_DEPENDENCY_INSTALL`도 해당 파일의 `vars`에 기록했다. 대시보드 값만 추가하면 빌드 시 덮어써지는 것을 로그로 확인했다.

기존 환경 변수·인증 비밀값·서비스 및 Hyperdrive 바인딩·호환성 설정은 API 수정 전후 비교로 보존을 확인했다. 이후 main push도 같은 설정으로 자동 배포된다. [Cloudflare 빌드 이미지 설정](https://developers.cloudflare.com/pages/configuration/build-image/).
